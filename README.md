# EMERALD — Beyond Reality

موقع Portfolio سينمائي لمبدع فيديوهات الذكاء الاصطناعي والتصاميم الرقمية. يتضمن الكود الكامل، الصور، المقاطع التصورية، نموذج التواصل، والملفات اللازمة لتشغيله ونشره.

## Concept

**Human vision. Artificial possibilities.**

الفكرة البصرية: الانتقال من فضاء أسود وجسم ضوئي زمردي إلى معرض تحريري هادئ، ثم العودة إلى الإضاءة الزمردية عند التواصل. الصورة والكتابة تقودان التكوين، وتستخدم الحركة لبناء العمق وإبراز الأعمال.

- هوية مؤقتة: **EMERALD**. تُستبدل باسم صاحب الأعمال أو الاستوديو.
- لوحة الألوان: `#050807` للخلفية، `#00FF9D` للضوء، `#EEF3EF` للنص، ودرجات خضراء هادئة للمعلومات الثانوية.
- الخط: Manrope محلي، مع خط monospace (JetBrains Mono) للترقيم والتصنيفات.
- Hero بملء الشاشة: مجسّم ضوئي، جسيمات WebGL، خطوط تجريدية، عنوان متحرك، وزر Magnetic Hover.
- الحركة: GSAP وScrollTrigger للكشف والعمق والتمرير، مع انتقالات CSS.
- الحركة اختيارية: احترام `prefers-reduced-motion`، وزر Motion في الأسفل لحفظ تفضيل الجهاز.
- لا يوجد صوت تلقائي أو تمرير إجباري. تشغيل الفيديو داخل نافذة المشاهدة يأتي بعد طلب الزائر.

## أهم ملفات الكود

- `app/portfolio.tsx`: الأقسام والتفاعلات والنوافذ والتواصل.
- `app/globals.css`: الهوية البصرية، التخطيط، والحركات وتجاوب الشاشات.
- `app/particle-field.tsx`: مشهد الجسيمات باستخدام WebGL الأصلي.
- `lib/portfolio-data.ts`: النصوص، بيانات الأعمال، التصنيفات، الخدمات ومراحل العمل.
- `app/layout.tsx`: العنوان والوصف وبيانات SEO.
- `app/api/contact/route.ts`: واجهة استقبال الطلبات.
- `lib/contact-validation.ts`: قواعد التحقق المشتركة بين المتصفح والخادم.
- `lib/enquiries.ts`: حفظ الطلبات باستعلام محضّر.
- `db/schema.ts` و`drizzle/`: بنية قاعدة البيانات وترحيلها.
- `wrangler.jsonc` و`open-next.config.ts`: إعداد نشر Worker وربط D1.
- `public/images/`: صور WebP جاهزة للويب.
- `public/motion/`: أربعة مقاطع MP4 صامتة، مدة كل منها ثماني ثوانٍ.
- `public/fonts/`: الخطوط ورخصة استخدامها.
- `scripts/create-motion-studies.py`: إعادة إنتاج المقاطع التصورية من الصور باستخدام FFmpeg.
- `tests/rendered-html.test.mjs`: التحقق من إخراج الصفحة وسلوك استقبال الطلبات.

## إضافة هويتك وأعمالك

1. استبدل اسم EMERALD داخل `lib/portfolio-data.ts` (المتغير `SITE`) وبيانات الموقع داخل `app/layout.tsx`.
2. عدّل تعريفك وبيانات الأفلام والتصاميم داخل `lib/portfolio-data.ts`.
3. ضع صورك داخل `public/images` وفيديوهات MP4 داخل `public/motion`، ثم حدّث مساراتها في البيانات.
4. حدّث أو أزل ملاحظة "Concept collection" عند استبدال الأعمال التصورية بأعمالك الأصلية. أضف فقط معلومات المشروع والعميل التي تخصك فعلاً.
5. يمكن تعديل صور `DesignArtwork` داخل `public/images`، أو استبدالها بعرض صور الأعمال الأصلية مباشرة.
6. حدّث روابط الهوية وعناوين SEO عند تغيير النطاق (`lib/portfolio-data.ts` و`app/layout.tsx`).

**مهم:** جميع الأعمال الحالية دراسات تصورية مولّدة لهذه التجربة، وليست أعمالاً سابقة لصاحب الموقع أو مشاريع لعملاء. المقاطع تحريك سينمائي قصير (Ken Burns) للصور، وليست أفلاماً أصلية مقدمة من المستخدم.

## نموذج التواصل

يرسل النموذج طلب JSON إلى `/api/contact` ويحفظه في جدول `enquiries` داخل قاعدة D1. الحقول هي الاسم، البريد، الرسالة، ووقت الإنشاء.

- التحقق يعمل في المتصفح والخادم (`lib/contact-validation.ts`).
- حجم الطلب محدود (8 كيلوبايت)، وتوجد خانة honeypot لرفض الإدخالات الآلية البسيطة.
- معرّف الطلب (`requestId`) يمنع تكرار حفظه عند إعادة المحاولة.
- النص يبقى في النموذج عند حدوث مشكلة.
- لا يوجد مسار عام لقراءة الطلبات.
- **لا يوجد إرسال بريد إلكتروني أو ربط بصندوق بريد حتى الآن.** يمكن لصاحب الموقع الاطلاع على الطلبات من قاعدة D1 مباشرة. إضافة إشعارات بريدية تحتاج عنوان المستلم ومزوّد إرسال مناسب.

## التقنية والتشغيل

Next.js 16 (App Router)، React 19، TypeScript، GSAP 3، WebGL الأصلي، Drizzle ORM، وCloudflare Workers/D1 عبر `@opennextjs/cloudflare`. تستخدم النوافذ والتبويبات والخدمات مكونات Radix (Dialog / Tabs / Accordion).

في بيئة Linux / Node.js 22 أو أحدث:

```bash
npm ci
npm run dev
```

بناء نسخة الإنتاج:

```bash
npm run build
```

اختبار إخراج الصفحة ومسار التواصل:

```bash
npm test
```

بعد تغيير بنية البيانات:

```bash
npm run db:generate
```

معاينة أو نشر Worker محلياً على Cloudflare (يتطلب حساب Cloudflare وتسجيل دخول `wrangler`):

```bash
npm run cf:preview   # معاينة محلية عبر Workers runtime
npm run cf:deploy    # نشر فعلي
```

تشغيل النموذج بشكل كامل يتطلب إنشاء قاعدة D1 حقيقية (`wrangler d1 create emerald-portfolio-db`)، وضع `database_id` الناتج داخل `wrangler.jsonc`، وتطبيق ترحيل `drizzle/0000_secret_phil_sheldon.sql` (`wrangler d1 migrations apply`). بدون هذا الربط، الخادم المحلي (`next dev` / `next start`) يستخدم بديلاً محلياً يحفظ الطلبات في ملف JSON تحت `.data/` — مناسب للتطوير والاختبار فقط.

## التحقق والحدود

- نجح بناء نسخة الإنتاج وفحص TypeScript (`npm run typecheck`).
- اختُبر إخراج الصفحة من الخادم مباشرة ووجود جميع الأقسام وبيانات العنوان (`npm test`).
- اختُبر مسار التواصل مع بيانات صحيحة وغير صحيحة، وrequest ضخم، وhoneypot، وإعادة الإرسال (dedup)، وفشل التخزين، باستخدام بديل محلي لقاعدة البيانات. لم تُرسل رسائل حقيقية خلال الاختبارات.
- فُحصت ملفات الصور والفيديو ومدة المقاطع (ثماني ثوانٍ) ومسارات الأصول.
- لم تُجرَ اختبارات متصفح آلية (Playwright) أو قياسات Lighthouse. لا يُدّعى تحقيق درجة أداء محددة أو التطابق مع جائزة تصميم.
- الصور الحالية دراسات مولّدة إجرائياً (تدرجات وضوء وخطوط)، وليست تصويراً أو تصميماً نهائياً — استبدلها بأعمالك الفعلية قبل الإطلاق.

مرجع تنفيذ الحركة: [GSAP ScrollTrigger](https://gsap.com/docs/v3/Plugins/ScrollTrigger/) و[GSAP matchMedia](https://gsap.com/docs/v3/GSAP/gsap.matchMedia()).
