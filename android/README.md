# تطبيق متقن لأندرويد (TWA)

هذا مجلد يحتوي على تطبيق أندرويد يعرض موقع متقن (www.motqen.site) داخل
تطبيق حقيقي قابل للتثبيت من Google Play، باستخدام تقنية
**Trusted Web Activity (TWA)**. أي تعديل تنشرونه على الموقع ينعكس مباشرة
داخل التطبيق دون الحاجة لإعادة بناء أو رفع نسخة جديدة.

## ما الذي يحتاج أن يكون جاهزًا على الموقع نفسه؟

تم بالفعل (في هذا الفرع) إضافة الملفين التاليين للموقع، وهما ضروريان
حتى يفتح التطبيق الموقع **بدون** شريط عنوان المتصفح:

- `/manifest.webmanifest` (عبر `app/manifest.ts`) — بيانات PWA الأساسية.
- `/.well-known/assetlinks.json` — يثبت لأندرويد أن هذا التطبيق مملوك
  فعلاً لموقع motqen.site (Digital Asset Links).

**مهم:** يجب نشر هذين الملفين على `www.motqen.site` قبل تجربة التطبيق،
وإلا فسيفتح الموقع داخل شريط متصفح مرئي (Custom Tab عادي) بدل ملء الشاشة.

## بنية المشروع

مشروع Gradle قياسي (نفس البنية التي يولّدها Google Bubblewrap):

```
android/
  app/
    build.gradle          # إعدادات التطبيق والتوقيع
    src/main/AndroidManifest.xml
    src/main/res/         # الأيقونات والألوان والنصوص
  build.gradle             # إعدادات المشروع الجذر
  settings.gradle
  gradlew / gradlew.bat    # لا تحتاج تثبيت Gradle يدويًا
  twa-manifest.json        # ملف مرجعي لأداة bubblewrap لو احتجتم تحديثه لاحقًا
  store-assets/            # أيقونة 512×512 لصفحة التطبيق على المتجر
```

- **Package name**: `site.motqen.twa`
- **اسم التطبيق**: متقن
- **العنوان المفتوح**: `https://www.motqen.site/`

## طريقة البناء

### الخيار الأول (موصى به): GitHub Actions

أضفنا Workflow جاهز في `.github/workflows/build-android-twa.yml` يبني
ملف `.aab` (لرفعه على Play Console) تلقائيًا. يحتاج فقط أن تضيفوا 4
أسرار (Secrets) في إعدادات المستودع على GitHub
(Settings → Secrets and variables → Actions):

| اسم السر | القيمة |
|---|---|
| `KEYSTORE_BASE64` | ناتج تشفير ملف التوقيع بصيغة base64 |
| `KEYSTORE_PASSWORD` | كلمة مرور ملف التوقيع |
| `KEY_ALIAS` | `motqen` |
| `KEY_PASSWORD` | نفس كلمة مرور ملف التوقيع |

ملف التوقيع (`.jks`) وكلمات المرور تم توليدها لكم وإرسالها في هذه
المحادثة — **لا يتم رفعها إلى git إطلاقًا**، فقط تُضاف كأسرار GitHub.

بعد إضافة الأسرار، شغّلوا الـ Workflow يدويًا من تبويب Actions، وسيُنتج
ملف `app-release.aab` جاهزًا لرفعه على Google Play Console.

### الخيار الثاني: بناء محلي عبر Android Studio

1. افتحوا مجلد `android/` كمشروع في Android Studio.
2. Build → Generate Signed Bundle / APK، واختاروا ملف التوقيع المُرسل
   لكم.
3. سينتج ملف `.aab` جاهز للرفع.

> **ملاحظة:** لا يمكن بناء نسخة موقّعة كاملة من داخل بيئة العمل الحالية
> لأنها لا تملك اتصالاً بخوادم Google لتنزيل Android SDK — لذلك جهّزنا
> مسار GitHub Actions كبديل عملي بدون الحاجة لتثبيت أي شيء على جهازكم.

## النشر على Google Play

1. أنشئوا حساب Google Play Console (رسوم لمرة واحدة 25$) إن لم يكن
   موجودًا.
2. أنشئوا تطبيقًا جديدًا، وفعّلوا **Play App Signing** (الخيار الافتراضي
   الموصى به من Google).
3. ارفعوا ملف `app-release.aab`.
4. **خطوة ضرورية بعد أول رفع:** من Play Console اذهبوا إلى
   `Setup → App integrity`، وانسخوا "SHA-256 certificate fingerprint"
   الخاص بـ **App signing key certificate** (وليس Upload key)، ثم
   أضيفوه كعنصر ثانٍ في مصفوفة `sha256_cert_fingerprints` داخل
   `public/.well-known/assetlinks.json` في مستودع الموقع، وانشروا
   الموقع من جديد. بدون هذه الخطوة سيظهر شريط المتصفح داخل التطبيق حتى
   لو كان مثبتًا من المتجر.
5. أكملوا بيانات صفحة التطبيق (وصف، لقطات شاشة، الأيقونة الموجودة في
   `store-assets/ic_launcher-playstore.png`، سياسة الخصوصية، إلخ) ثم
   أرسلوه للمراجعة.

## تحديث محتوى التطبيق لاحقًا

لأن التطبيق TWA هو غلاف حول الموقع فقط، أي تعديل على الموقع (نصوص،
صفحات، صور) **لا يحتاج بناء تطبيق جديد أو رفعه للمتجر**. تحتاجون فقط
لبناء ورفع نسخة جديدة من التطبيق عند:

- تغيير الأيقونة أو اسم التطبيق أو الألوان.
- رفع نسخة تجريبية أولى (Google تطلب على الأقل رفعة واحدة موقعة).
- تغييرات على مستوى الأندرويد نفسه (صلاحيات، الحد الأدنى لنسخة أندرويد، إلخ).
